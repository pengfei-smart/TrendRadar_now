# TrendRadar A股免费行情接口选型 V1

## 结论

第一版选择东方财富公开批量报价接口作为主行情源：

- Endpoint: https://push2.eastmoney.com/api/qt/ulist.np/get
- 用途：只拉取事件映射形成的候选证券，不逐只请求全市场。
- 参数：secids按交易所拼接；fields请求价格、涨跌幅、成交额及候选附加字段。
- 默认batch_size=100，配置上限500；候选集超过batch size才分批请求。
- 目前通过 requests，不引入额外行情SDK。
- 数据源非官方、没有公开的服务级别协议（SLA），并可能触发访问限制。必须限速、超时、错误重试/降级并记录来源。

## 为什么使用候选批量而非全市场分页

雷达设计是新闻/事件→映射候选股票→行情确认。直接按secids批量获取：
- 请求量跟候选股票数量相关，而不是全A股数量；
- 避免全市场按涨跌幅排序分页时，行情变化造成的分页漂移；
- 返回结果可以严格校验只属于请求候选池；
- 如果接口失败，雷达市场部分降级为unavailable，不中断新闻抓取与原新闻推送。

## 字段映射

| 东财字段 | QuoteSnapshot字段 | 说明 |
|---|---|---|
| f12 | code | 六位证券代码 |
| f2 | price | 最新价格；缺失或0视为无有效报价 |
| f3 | change_pct | 涨跌幅百分比 |
| f6 | turnover | 成交额（元） |
| f10 | volume_ratio | 量比（仅响应提供时填充） |
| 请求采集时间 | timestamp | 采集时刻，不等同于交易所行情时间 |
| provider名称 | source | eastmoney_ulist |
| 固定true | delayed | 当前不能由该接口确认逐笔时间，明确按延迟/时间未验证标记 |

## 限制与防护

- 不假定请求频率无限，也不声称该公开接口保证实时或免费商用。
- 连接/读取超时设置；响应必须为可解析JSON且diff结构正确。
- 证券代码规范化，过滤非候选证券、重复返回和无价格数据。
- 请求错误、空数据或所有provider失败会抛出QuoteSourceError，调用方应记录失败状态，不得误报“无机会”。
- 每次扫描记录provider和采集时间；通知文案应标注“行情时间未由源端确认/可能延迟”。
- 用户候选集如果过大，应在业务映射层设置合理上限，并对每个batch按固定间隔请求。

## 备用数据源评估

### 新浪财经公开报价
社区实现常使用新浪财经行情接口，但端点/编码格式和响应协议有变动风险；第一版暂不直接将它作为自动fallback，避免在未通过字段对照测试时混用错误报价。下一轮可实现一个独立SinaQuoteProvider，与东财在同一候选清单上对照：
- code覆盖（含沪深京）
- price/change_pct/turnover一致性
- 成功率、响应耗时和数据时间
- 限流或访问拒绝后的表现

### AkShare
AkShare是数据访问库而非单一官方行情源，部分接口底层依赖东财/新浪等网页端。引入会增加依赖和接口变更面；当前项目依赖尽量保持requests，因此第一版不增加AkShare依赖。后续若实测证明能提升覆盖/稳定性再讨论。

## 开发验收标准

- batch_size=1/多批次请求测试。
- JSON diff数组与对象两种格式解析测试。
- 数值字段缺失、异常、0价格测试。
- 候选代码外结果、重复代码结果防护。
- primary异常时能调用后备provider；全部失败时返回明确失败，而不是空机会列表。
- 与真实市场数据做人工小样本对照前，不启用14:33实盘推送。
