# 交易所权威上市状态校验设计

## 目标与范围

证券身份清单与上市生命周期状态必须分层：
- 东方财富 clist 当前只承担证券身份发现、代码、简称、交易所和板块识别。
- listing_status 只能由可追溯的权威状态快照确认，禁止因身份清单缺少状态字段而默认 active。
- 目标候选范围为沪市主板A股、深市主板A股和创业板；北交所、科创板不进入候选池，但可保留证券身份记录。
- 停牌是交易状态，不等同于终止上市；短线候选还需独立交易状态检查。

## 已核实的官方资料

### 上海证券交易所

官方“股票与存托凭证 - 股票列表”页面提供股票、首次发行待上市股票、暂停/终止上市公司等分类，并支持“主板A股”板块筛选：
- 页面：https://www.sse.com.cn/assortment/stock/list/share/
- 官方页面可见分类不代表已确认存在稳定、公开、可依赖的机器接口。
- “暂停/终止上市公司”将两种状态放在同一分类中；若底层数据不能区分暂停与终止，适配器不得自行猜测具体状态，应标为 inactive/unknown 并排除候选池，或使用官方公告进一步确认。

### 深圳证券交易所

官方市场体系资料明确深市由主板和创业板构成：
- 页面：https://www.szse.cn/www/marketServices/listing/select/marketSystem/index.html
- 《深圳证券交易所数据文件交换接口规范》定义主板A股、创业板股票等证券类别：
  https://investor.szse.cn/marketServices/technicalservice/interface/P020210108608099171931.pdf
- 上述规范可用于核对证券类别定义，但不能单独证明某个证券当前仍上市。
- 官方“上市公司”公告页可用于公告级补充核验：
  https://www.szse.cn/disclosure/notice/company/index.html
- 当前尚未确认一个可稳定自动获取完整现行主板A股与创业板名单的公开接口。

## 状态判定规则

1. active：仅当代码出现在对应交易所、对应板块的完整且通过校验的现行上市名单中。
2. delisted：仅当权威终止上市名单或正式终止上市公告明确确认。
3. suspended：仅当权威来源明确表示暂停上市/停牌；不得把行情价格为0作为依据。
4. pending：仅当权威首次发行待上市名单明确确认。
5. unknown：来源缺失、抓取失败、名单不完整、来源无法区分状态、代码无法匹配等所有无法确认情形。

只有 active、非风险警示、符合目标板块的证券可以进入候选池。unknown、pending、suspended、delisted 均排除。

## 快照采集与原子更新要求

每个交易所适配器必须返回：
- source_id、source_url、exchange、board_scope
- fetched_at、source_as_of（若官方提供）
- active_codes，以及可可靠区分时提供的 suspended/delisted/pending codes
- 原始总量、解析总量、去重后数量、分页/文件完整性信息

写库前必须校验：
- HTTP成功、响应结构/文件格式正确、代码格式合法。
- 不允许跨交易所或跨板块混入证券。
- 各状态集合不得有交集；重复代码必须报错。
- 名单数量不得为空或明显异常；覆盖率和与上一份成功快照的变化须经过阈值检查。
- 多个来源任一关键来源失败时，不得把部分名单当成全量快照。
- 校验通过后在一个事务内应用整份状态快照；失败时保留上一份成功状态和来源时间戳。

## 与证券身份更新的交互

- clist刷新得到 unknown 时，不得将已由权威快照确认的状态覆盖成 unknown；身份字段更新与状态字段更新应分开写入。
- 首次运行或没有有效权威状态快照时，证券状态保持 unknown，候选池安全降级，不得放行。
- 不能仅凭某次权威名单缺席就判定 delisted；必须有明确终止上市证据。缺席代码保持 unknown，直到权威终止信息确认。
- 对来源过期的状态快照应设置有效期；过期后状态不再作为强active依据，候选池降级并报告 freshness。
- 保留历史证券身份和状态变更记录，避免删除证券或覆盖历史证据。

## 实现顺序

1. 先完成交易所官方页面/接口的机器可读端点确认和真实响应样本留档。
2. 分别实现上交所主板A股、深交所主板A股、深交所创业板适配器。
3. 为每个适配器编写响应解析、分页完整性、重复代码、空快照和字段漂移测试。
4. 实现跨来源合并与状态快照原子写入，并记录 source/as_of/fetched_at。
5. 用已确认退市的历史样本（包括600991、601028、601059、601198、601299、601989、603056）验证不再进入候选池。
6. 最后再运行1000只及更大规模行情基准；不能把状态未知的证券计入合格候选池。

## 适配器实现与验证边界

- 已新增 `listing_status_provider.py`：上交所主板A股适配器、深交所A股XLSX适配器（拆分主板/创业板）和三板块更新协调器。
- 上交所适配器请求官方 `query.sse.com.cn/sseQuery/commonQuery.do`，使用 `STOCK_TYPE=1`、`COMPANY_STATUS=2` 和官方 SQL 查询标识；该参数组合尚未在本项目运行环境完成真实响应验证，必须以实测响应字段和数量确认后才能投入生产。
- 深交所适配器请求官方 `www.szse.cn/api/report/ShowReport` 的 `CATALOGID=1110` XLSX 数据；列名和板块值已做严格校验，尚未完成真实响应验证。
- 新增 `openpyxl` 用于解析深交所 XLSX 文件。
- `ExchangeListingStatusUpdater` 会先获取并验证三个板块，再通过单个 SQLite 事务提交全部快照；任一来源获取或校验失败时不写入任何一份。
- 当前快照只给名单内证券提供 `active` 正向证据；已知证券若在完整名单中缺席，会降级为 `unknown`，绝不据此推断 `delisted`。
- 自动化单元测试已加入，但尚未由最新 GitHub Actions 运行结果确认通过。

## 当前实现状态

- 东方财富证券身份数据缺少可验证的 listing_status 时已改为 unknown。
- 候选池过滤要求 listing_status == active，因此未知状态会被安全排除。
- 交易所权威机器接口尚未确认，交易所适配器和状态快照写库尚未实现。
- 本文件是实现约束，不代表交易所数据已经接通或退市样本已经完成自动校验。
