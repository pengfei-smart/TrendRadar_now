# A股证券主数据更新方案

## 数据源与限制
- 首版采用东方财富公开证券列表 clist endpoint 作为探索性免费数据源。
- 该接口非交易所官方接口，可能调整字段、筛选表达式、分页策略或访问限制；不承诺SLA。
- 每次更新必须记录数据源和采集时间。源接口响应异常时，保留上一版主数据，不执行写入。
- 后续可以增加官方交易所/其他数据源作为校验与fallback；不同来源需独立解析并交叉校验。

## 首版更新流程
1. 分页请求全量A股证券清单。
2. 验证返回总量、分页稳定性、空页和字段结构。
3. 将股票代码规范为六位字符串，推断交易所与板块。
4. 从证券简称识别ST、*ST、S*ST等风险警示前缀。
5. 校验重复代码、空名称、无效交易所和上市状态。
6. 比较本地证券数：源数据低于最低阈值或较本地数量骤降超过20%则拒绝。
7. 校验通过后在SQLite事务内UPSERT；不因单轮源数据缺失删除或标记退市。
8. 记录采集结果和错误摘要。

## 证券状态语义
- listing_status 表示证券上市生命周期状态，不代表此刻是否停牌。
- 当前公开clist证券清单未作为停牌状态的权威来源；首版将上市证券状态标记为active。
- 停牌应由行情/交易状态数据层单独判断，并在扫描候选过滤阶段剔除。
- 风险警示状态从名称前缀检测并保存risk_flag；证券简称变更时每次更新重新计算。
- eligible_securities仅过滤风险警示和非active上市状态。实际停牌过滤待行情服务接入。

## 阈值与保守策略
- 最低默认数量：1000（配置可调，测试可降低）。
- 对比已有主数据下降比例超过20%拒绝覆盖（配置可调）。
- 代码重复、名称缺失、页间总量变化、分页不完整、源数据异常均拒绝整个快照。
- 新源数据没出现的旧证券暂不自动退市。后续通过权威退市列表/多轮全量确认处理。
- 上述数量阈值是保护措施，并非市场总证券数的固定断言；随A股扩容需要复核配置。

## 使用方式（接入阶段）
调用 `EastmoneySecurityMasterProvider.fetch_all()` 获取规范化证券列表，再交给 `SecurityMasterUpdater(provider, storage).update()`。当前提交只提供模块与单元测试，不触发任何工作流、定时更新或线上推送。
